# Subprocess workers

The Rust subprocess executor launches installed worker commands. A worker with
namespace `hello_world` is discovered as `tkr-hello-world-worker`; packages
generated by `tkr init worker` install a compatible entry point.

Inputs are copied from the executor's configured asset storage before launch,
and outputs are saved to `output_storage_name` when the worker finishes. The
worker receives the runtime-generated call definition rather than a collection
of controller-specific environment variables.

The default runtime already defines a `subprocess` executor using file-backed
assets. Override it when a deployment needs different named stores:

```toml
[asset_storage.shared]
type = "File"
asset_dir = "/shared/tierkreis/assets"

[executors.subprocess]
type = "Subprocess"
subprocess_storage_name = "shared"
output_storage_name = "shared"
```

The legacy `ShellExecutor` and `StdInOut` adapters are not part of the Rust
runtime. Package external programs behind the Tierkreis worker protocol, or
configure an explicit worker command on an HPC executor.
